# Eclesiar 助手（Eclesiar Helper）

一个为 [Eclesiar](https://app.eclesiar.com/)（多人在线经济 / 政治模拟游戏）准备的油猴（Tampermonkey）辅助脚本。

当前版本 **v0.2.3**：常驻悬浮球 + 可展开面板，内置「全球汇率总览」「各国市场商品金价比价」与「工商 · 工业 / 税费」。汇率页的换汇目标可在「黄金 / 法币」之间一键切换，列表顶部还会置顶玩家国籍与当前所在国的汇率（两种配色 + 文字标签区分），不用在长长的列表里找自己的货币。商品页可在「采购 / 销售」之间切换：采购按黄金单价从低到高，销售先扣增值税与进口税、再按卖币换金汇率算出实际黄金收入并从高到低排列。已失去全部领土的流亡政府会被单独剔到底部一栏，避免按到不了的报价做决策。列表里每一行右侧都带一个箭头按钮，一键跳到游戏对应页面：汇率行打开该货币的货币市场，商品行打开该国商品市场并自动带上当前选中的商品与品质。游戏自己的「商品市场」列表也会直接在每行起价下面标注折算后的黄金单价，并标出比全球最低价贵多少；上架表单底部的「实收金额」右边同步显示折算金价；「商品市场」页的「你当前不在该国家」提示下方还会列出该国拥有的地区，点一下直接打开对应的地区页面。「商品」页另有「自动展示商品比价」（默认关闭，开启前会提示请求量）：开启后插件启动即预抓全球汇率与商品行情，不打开面板也能在商品市场看到与全球最低价的对比，行情每 10 分钟自动更新。商品用两行图标按钮点选（成品 / 原材料，成品再选 Q1–Q5 品质）；检查更新与安装走 jsDelivr，国内打不开时可在「设置」页改用 JSDMirror 镜像地址。「设置」页可一键生成专用 API 密钥，插件查询不再占用游戏操作的每日额度。新的「工商」页下挂「工业」「税费」两个子面板：「工业」一次拉全服所有地区，按国家旗帜、地区、资源产区、工业区、物产、污染度、NPC 数量列成一张可排序的表，每行右侧一键跳到该地区的游戏页面；「税费」把各国税负列成一张可排序的表：第一行增值税 / 进口税 / 工资税，第二行税前最低工资（含折算金价）与最低工资税金（折算金价）；默认「综合」按（增值税 + 进口税）从低到高、同值按最低工资税金由低到高，搜索框与排序标签固定在顶部只有列表滚，还能按中英文国名 / 法币筛选。业务功能以「功能（feature）」形式注册接入，外壳无需改动。

> 非官方工具，与 Eclesiar 官方无关。请遵守游戏规则。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/)（或 Violentmonkey）。
2. 点下面的安装地址，在油猴的安装页里确认：
   - 推荐（jsDelivr 官方源）：<https://cdn.jsdelivr.net/gh/Billdex/eclesiar-helper@main/eclesiar-helper.user.js>
   - 备用一（JSDMirror 国内镜像）：<https://cdn.jsdmirror.com/gh/Billdex/eclesiar-helper@main/eclesiar-helper.user.js>
   - 备用二（GitHub 直链，能访问 raw 的网络用）：<https://raw.githubusercontent.com/Billdex/eclesiar-helper/main/eclesiar-helper.user.js>
3. 打开 <https://app.eclesiar.com/> 并刷新，右下角出现金色悬浮球即生效。

三个地址装的是同一份脚本，点得开哪个用哪个。`cdn.jsdelivr.net` 是官方主源，多数网络可用；国内如果被限速或打不开，用 JSDMirror 那个（路径规则完全相同，只是把域名换成 `cdn.jsdmirror.com`）；`raw.githubusercontent.com` 在国内经常直接被拦，点开只会一直转圈或空白。也可以把 `eclesiar-helper.user.js` 下载下来拖进浏览器窗口安装。

脚本只匹配 `https://app.eclesiar.com/*`，不会在官网、Wiki 或其它站点运行。

调试日志：在游戏页面地址后加 `?eh-debug=1`，控制台会输出插件日志。

## 更新

- **默认都走 jsDelivr**：脚本头部的 `@updateURL`（元数据）与 `@downloadURL`（脚本本体）都指向 `https://cdn.jsdelivr.net/gh/Billdex/eclesiar-helper@main/…`。Tampermonkey 定期检查更新时只拉几 KB 的元数据并比对 `@version`，**只有版本号变大才下载完整脚本**。
- 面板「设置」页打开时会自动检查一次最新版本，同样只读元数据；失败可以点「重新检查」。
- 发现新版本时「设置」页会出现「安装更新」按钮（指向 jsDelivr），点击后由 Tampermonkey 提示覆盖安装，本地的界面设置（悬浮球位置、上次所在标签页）会保留。
- 面板里的检查把 `cdn.jsdelivr.net`、JSDMirror（`cdn.jsdmirror.com`）、JSDMirror 备用域名 `cdn.jsdmirror.cn` 与 GitHub raw 四个源**并行**问一遍（每个源单独限时 4 秒），取其中最高的版本号——某个源缓存落后也不会漏掉更新。全部读不到时才提示失败，并保留三个手动安装链接。检查时会给地址加一个时间戳参数，绕开边缘节点上的旧缓存；CDN 中间层对「分支」的解析缓存不受这个参数影响，所以刚发布的几分钟到几小时内，仍可能出现「本地已是最新、CDN 还返回旧版本」——这是 CDN 侧的延迟，多刷几次或过一会儿再检查即可。
- 油猴只支持一个 `@updateURL`，所以自动更新通道固定用 jsDelivr；它万一不可用（国内被限速或拦截时），可以在「设置」页点「备用（JSDMirror）」或「备用（GitHub）」手动覆盖安装，面板里的版本检查本身也会从镜像读到新版本号。
- JSDMirror 只是镜像，不参与自动更新，也不需要作者提供任何密钥；它自身对 `@main` 分支另有缓存，偶尔会比 jsDelivr 旧一些，多刷几次即可。

## API 密钥与每日额度

游戏对部分公开数据的查询有「每日次数上限」。插件的汇率与商品比价一轮就会发上百次请求，如果直接用你游玩时的登录凭据，活跃玩家很容易把当天额度用光，影响正常游玩。

「设置」页的 **API 访问** 栏目会显示当前用的是哪套凭据：

- **API 专用密钥**：插件的所有公开数据查询都用它，不再和游戏内操作共用额度。
- **登录凭据（临时）**（显示为红色）：还没保存密钥，插件暂时借用登录凭据（额度共用），下方会提示建议生成专用密钥。
- **API 专用密钥（已失效）**：保存的密钥被接口拒绝了（例如在游戏里删除了），重新生成或粘贴一个新密钥即可。

获取方式有两种：点「生成专用密钥」由插件调用接口自动生成（用的是你当前的登录凭据，生成后立即保存）；也可以点「接口文档 / 管理密钥」跳到游戏的 API 页面自己生成，把 `eclesiar_prod_…` 粘贴到输入框保存。密钥只保存在本机 `localStorage`，不打印、不上报，点「移除密钥」即可删除；「清除本地设置」不会动它。

拿到密钥后，回到「汇率」/「商品」标签点一次「刷新行情」即可，之后刷新游戏页面也会自动继续使用。

「商品」页的「自动展示商品比价」会在插件启动和缓存过期时各抓一轮全球行情（每轮上百次请求），请求量明显大于手动刷新，建议先配置专用 API 密钥再开启，避免挤占游戏内的每日查询额度。

使用专用密钥时，每次进入「设置」页都会读取一次当日用量，显示「已用 / 上限（剩余）」，下面给出距 UTC 零点重置的倒计时（每分钟本地刷新）和统计日期。用量只在进入页面时请求一次，不做定时轮询。

## 汇率总览

打开面板的「汇率」标签，点「刷新行情」即可拉取一次全球所有法币的挂单。

**价格口径**（单位统一为「黄金 / 1 单位法币」，可直接横向比较）：

- **买入**：你花黄金买该国法币，吃的是别人出售法币的挂单（`transaction=SELL`），价格越低越好。
- **卖出**：你卖该国法币换黄金，吃的是别人用黄金收货的挂单（`transaction=BUY`），价格越高越好。

这两类挂单的数量字段口径不同：卖单的 `amount` 是法币数量（`rate` 就是金/法币），买单的 `amount` 是黄金数量（`rate` 是法币/金）。插件会统一换算后再展示，所以列表里的两个价格可以直接比价，最优价后面紧跟的均价也是同一口径。

**每行怎么读**：一个方向占一行——`买入 0.0400` 这种彩色徽标是该方向的**最优价**（吃第一档），后面紧跟按目标额度成交的结果（`🪙10 → 245.2 KRW`）。只吃了一档、均价与最优价几乎一样时不再重复写均价；吃满并吃了多档时行尾补一个「均价」；没凑够目标额度（挂单深度不够）时，徽标里的价格直接换成这笔的**成交均价**并在前面标「均价」，行尾只留「深度不足」与实际成交的黄金量，不再重复写一遍。

**目标额度**：输入框里的数字默认 10；输入框左侧的口径标签带一个切换图标，点一下就在「目标黄金 / 目标法币」之间切换——只是换口径（这个数字是黄金还是法币），值本身保持不变；改动后立即重算（不发请求）。清空输入框时不会立刻被填回 10，可以留着空继续输入；只有失焦、回车或切口径时才把上一次的有效值补回来。插件会从最优档位开始逐档吃单，直到凑够目标金数或目标法币数量，得到成交量加权的平均成本；如果该方向的挂单深度不够，会在行内标注「深度不足」并显示实际能成交的量，而不是假装按目标额度全部成交。

**置顶本国汇率**：列表上方固定显示两行——先是你**国籍**对应的法币，再是你**当前所在国家**的货币，两行用不同颜色的边框 / 背景与「国籍」「当前所在国」标签区分；两种货币相同时合并成一行。数据来自 `POST /account/getuser` 里的国籍与所在国 id（只读这两个字段，与「商品」共用一份 2 分钟缓存），再按国家清单换成货币；这两行在全球列表里不再重复出现。还没拿到登录凭据时会在原位提示，读到账号后自动补上；行情没拉过时显示「未加载」，不会误写成没有挂单。

**国名与国旗**：游戏没有中文翻译，列表里的中文国名（以及英文名前的国旗）来自插件内置的对照表，按法币代码索引；接口以后新增货币时查不到就只显示英文国名，不影响使用。国旗优先用 `countries/summary` 返回的 `avatar` 图片，图片缺失或加载失败时退回国旗 emoji，两者都没有就留空不占位。

**加载过程**：点「刷新行情」后，插件先按货币清单把每一行摆出来，行右侧显示一个小转圈；某个货币的挂单回来就地填数、转圈消失，两侧都没挂单的行直接移除，请求失败的货币则标注「挂单拉取失败」（串行补拉一次仍失败才会显示）。全部结束后列表按买入均价从低到高重排一次——加载过程中不排序，避免边填数边跳行。

**凭据**：接口需要 `Authorization: Bearer <凭据>`。插件优先使用你在「设置」页保存的专用 API 密钥；没有密钥时才临时借用游戏自己的登录 JWT（只从游戏发往 `api.eclesiar.com` 的请求头里读一次，仅存页面内存，不写 `localStorage`、不打日志、不上报）。因此：

- 刚打开游戏还没触发过接口请求时，面板会提示「尚未拿到登录凭据」，在游戏里点开任意页面让它发一次请求，再点「刷新行情」即可。
- 登录凭据过期时接口返回 401，插件会清掉内存里的旧凭据并提示刷新页面；专用密钥被拒时只提示密钥失效，不影响刷新页面后重新生成。

**请求规模**：45 种法币 ×（SELL + BUY）≈ 90 次请求，3 并发、每次间隔 60ms，列表逐行填充并显示进度；个别失败的货币会串行补拉一次。只在你点「刷新行情」或首次打开该标签时触发，**不会定时轮询**（「自动展示商品比价」开启时，会随商品行情一起按 10 分钟缓存自动更新），加载期间按钮禁用。

**已知限制**：未计入游戏可能收取的市场手续费；挂单随时会变，均价只代表抓取那一刻的订单簿；列表按买入均价从低到高排序，买不到的方向排在最后。

## 商品比价

打开面板的「商品」标签，第一行点选 4 种成品（食物 / 武器 / 飞机 / 机票），第二行点选 4 种原材料（谷物 / 铁 / 燃料 / 钛）；选中成品时下面会多出一行 Q1–Q5 品质（沿用上次选的品质），选中原材料则没有品质。列表会按**黄金单价从低到高**列出各国市场。

**图标**：按钮上优先显示挂单接口 `avatar` 里的商品图，每拉完一个市场就补一批（哪个市场先返回就先换哪几件），不用等全部拉完；接口没给或图片加载失败时退回内置 emoji，不影响选择。

**为什么折算成黄金**：各国市场用当地货币计价，直接比数字没有意义；黄金是全局硬通货，而当地货币本身也能用黄金在货币市场买到，所以「买 1 件商品要花多少黄金」才是可横向比较的口径。

**计算口径**：

- 取该国市场里该商品最便宜的一档挂单（同一国家可能有多条报价）；
- 买方只付挂单价本身：国家法律里的进口税（`laws.import_taxes`）是境外卖家成交后被扣的税，不加到买方成本里，所以这里不做任何加价；
- 黄金单价 = 挂单价 × 用黄金换该国货币的**最优卖单价**（与「汇率」标签的「买入」价同一口径）；
- 鼠标悬停在行内说明上，可以看到这一步的乘式。

**无汇率**：如果该国货币在货币市场没有任何挂单，「汇率」里也就没有它的价格，这一行会显示 `—`、排到最后，并标注「该国货币暂无换汇挂单」。

**流亡政府**：商品交易必须人站在该国领土上才能下单，所以国土被战争打光、只剩流亡政府的国家即使还挂着旧单，实际上也已经没人能去成交。插件会核对每个有挂单的国家还剩不剩领土（`GET /country/regions?country_id=…`；已失去全部领土的国家不会回空数组，而是只有 `{ "code": 200, "description": "成功" }`、连 `data` 都没有，两种形态都按流亡政府处理），把这些国家从主列表里剔除，单独放到最底部的「流亡政府 · 已失去全部领土」一栏，栏首写明原因；栏内仍按同一套规则排序，名次位置显示 `—` 表示不参与排名，也不会拿到「最优」高亮。

**请求规模**：接口在不带 `type` / `quality` 时会一次返回该国市场的全部商品，所以每个国家只需 1 次市场请求；有挂单的国家再加 1 次领土请求（该接口只发 GET——同一地址的 POST 会 404，插件不会去试；结果缓存 5 分钟，5 分钟内再刷新不重复查）。47 个国家约 47 + N 次，3 并发、每次间隔 60ms。默认在你打开或切回该标签、或点「刷新行情」时触发（10 分钟内不重复请求），不会定时轮询；开启「商品」页的「自动展示商品比价」后，**游戏市场页**也会在启动时预抓一轮、之后按 10 分钟缓存过期再抓（只在前台标签页，失败退避 5 分钟），与面板共用同一份快照。领土查不到（超时 / 429 / 接口报错）时一律按「有领土」处理，国家留在主列表，不会把正常国家误判成流亡政府；这种降级只在调试日志（`?eh-debug=1`）里记录，不占用状态栏。

**缓存**：汇率复用「汇率」标签的行情（10 分钟内有效）。刚看过汇率再来商品，只会拉各国市场，不会重复拉那一百来次换汇挂单；反过来先看商品，汇率标签也会直接用这份数据。

**已知限制**：未计入游戏可能收取的手续费；报价是抓取那一刻的挂单，随时会变；「可买 N」是最低价那一档的剩余数量，买得更多就要吃下一档更贵的价格。

## 销售参考

商品页顶部的「采购 / 销售」切换共用同一份各国挂单，只换本地计算与展示，切回切走不会重新请求市场。

**为什么要单独算**：采购是把挂单价按「花黄金买该国货币」的汇率折成黄金；销售要先去目的国扣税，再按「卖该国货币换黄金」的**相反方向**折算，税费和汇率方向都不同，不能直接拿采购的黄金单价当收入。

**计算口径**：

- 挂单价取该国市场该商品最便宜的一档（商品市场只有卖单，要和其他卖家竞争，最多也就卖到这个价）；
- 卖家实得 = 挂单价 ×（1 − 增值税 − 进口税）。税率来自 `countries` 接口的 `laws.vat` / `laws.import_taxes`（百分数），两项按挂单价分别直接扣除，不倒推、不复利；
- 在账号国籍所属国家销售时免进口税，只扣增值税；拿不到国籍时按外国卖家处理，两项都扣；
- 税后黄金收入 = 卖家实得 × 卖该国货币换黄金的最优价（与「汇率」标签的「卖出」价同一口径）；
- 列表按税后黄金收入从高到低排；最显眼的数值就是税后收入，下面一行先给税前黄金，再给增值税 / 进口税比例（税后不重复写）；鼠标悬停可看完整乘式；缺换汇买单或税率的行会标注原因并排在最后，换汇买盘连 1 件的所得都吃不下时标注「换汇深度不足」。

**国籍来源**：进入「销售」时用 `POST /account/getuser` 读取当前登录账号的国籍。该接口只认游戏登录凭据（带专用 API 密钥会 401），所以即使配置了密钥也用登录凭据发；`/account` 是按 `account_id` 查指定用户，不适用。只读 `nationality.id` / `nationality_id` 判断是否本国，仅存页面内存、不展示原始字段、不落盘、不打日志；响应里的其它账号字段（包括 `bearer`）一律不读、不存。国籍读取失败或账号没有国籍时按外国卖家计税，并在提示里说明。

**请求规模**：进入「销售」时额外请求一次 `countries`（拿税率）和一次账号信息（拿国籍），之后切走再回来直接复用；读取失败会提示并暂按 0 税估算，再点一次「销售」会重试。

**已知限制**：未计入手续费；商品市场只有卖单，没有「可卖数量」可参考，报价就是别人当前挂出的最低卖价；换汇买盘深度不足时实际到手会低于显示值。

## 市场列表与上架表单金价标注

打开游戏自己的「商品市场」页（`/market`），插件会在两处补上折算金价：

**列表行**：每行「起价」下面补一行小字「≈ + 金币图标 + 金额」（例如 `≈ 🪙 0.0169`），把这一行的起价直接折算成黄金，不用来回对照「汇率」标签。

**上架表单**：右下角上架面板里，底部那行的「实收金额」右边补一行同样样式的小字。上架价本身不带币种，插件按「当前所在国家市场的本币」换算——所在国家取自 `POST /account/getuser` 的 `region.country.id`（只存内存），再对应到该国的货币；因为这是**卖出去的收入**，用的方向是「卖币换金」的买单最优价，而不是买币的卖单价。改了单价或数量后，这一行会跟着实时更新。所在国家读不到、该国货币没有买单时静默跳过（或标「暂无换汇买单」）。

- **只加不改**：往价格单元格 / 表单行追加一段只读文字，不改游戏原有节点、文本、按钮与点击行为；关掉开关或 `EclesiarHelper.destroy()` 时全部移除，页面恢复原样；
- **口径（列表行）**：挂单价 × 用黄金换该国货币的最优价，与「商品比价」的采购口径一致，同样不含手续费；鼠标悬停可看完整乘式；
- **口径（实收金额）**：实收金额（已扣增值税与进口税）× 卖币换金最优价；悬停可看到完整乘式与所用国家 / 币种；
- **比全球最低贵多少**：有全球行情时，列表行标注会多一段对比——`+0.0078` 表示这行比全球最低价（排除流亡政府）贵 0.0078 金，`最低` 表示当前就是全球最低（差额不足 0.5% 也按最低算）；悬停可看到最低价在哪个国家、具体差多少。行情有两个来源：打开一次面板「商品」页，或在「商品」页开启「自动展示商品比价」。默认关闭时不会为这个参考值去拉 45 个国家的市场，只显示本国折算价；开启后插件启动就预抓一次，并且按 10 分钟缓存自动更新（只在前台标签页，失败退避 5 分钟），不打开面板也能比价。开启前会明确提示一轮上百次请求、可能拖慢启动并消耗额度；
- **汇率来源**：优先复用「汇率 / 商品」标签已经拉过的那份缓存；没拉过时按页面上出现的货币各查一次对应方向的挂单（每种货币最多 1 次，缓存 5 分钟），不轮询；上架表单的所在国家每次进入页面读一次（缓存 2 分钟）；
- **异常提示**：该国货币没有换汇挂单时显示灰色「暂无换汇」/「暂无换汇买单」；认不出货币或还没拿到凭据时静默不标，只在 `?eh-debug=1` 的日志里留一行记录；
- **只在商品市场页生效**：跟随 SPA 路由进出，离开页面立刻摘掉全部标注，不会标到货币市场、股票市场等其它页面；
- **金币图标**：金额前面统一用游戏 CDN 的黄金图标（`storage.eclesiar.com/medias/41.png`）代替「金」字，面板里的汇率、商品、销售各处同步改；图片加载失败时自动退回「金」字，不留破图；
- **开关**：面板「商品」页底部的「商品市场与上架表单显示金价」，两处标注共用一个开关，默认开启，状态记在 `localStorage`。同一个区域下面还有默认关闭的「自动展示商品比价」，见上文。

## 工商 · 工业

面板的「工商」页是工商类数据的入口，目前下挂「工业」「税费」两个子面板（以后会在这里继续加子面板，顶层标签不用改）。

**这份表解决什么**：建厂、升级资源产区 / 工业区之前，想知道全服哪些地区值得去。列表把每个地区的建筑等级、物产加成、污染和 NPC 摆在一起，可以按任意一列排序。

**数据**：`GET /country/regions?country_id=…`，一次返回该国目前实际占有的地区：

- `buildings.production_fields.level` → 资源产区等级（接口字段名是 production fields，界面上叫「资源产区」）；
- `buildings.industrial_zone.level` → 工业区等级；
- `bonus[]`（`type` / `value`）→ 物产与加成百分比（食物 / 武器 / 票券 / 谷物 / 铁 / 石油 / 钛 / 飞机）；
- `pollution` → 污染度（百分数）；
- `nb_npcs` → NPC 数量。

国旗与国名取自 `countries/summary` 的 `avatar` / `name`（内置中文国名），占领后按 `region.country_id` 跟着现主人走。已失去全部领土的流亡政府本来就查不到地区，不会出现在列表里。

**默认排序（「综合」）**：

1. 先按「凑齐几项」分档：工业区 + 资源产区 + 物产 三项齐全 > 有工业区 + 资源产区（或有工业区 + 物产）> 只有工业区 > 只有资源产区 > 只有物产 > 什么都没有。这样既保证「工业区优先于资源产区」，也不会把物产很好的地区压到最后；
2. 同一档里按综合分从高到低：`（工业区 + 资源产区 + 物产加成）×（1 − 污染%）`。物产按 5% / 15% / 30% 折算成 0.5 / 1.5 / 3 分，和建筑等级同一量级；污染按扣减计算，污染越低越靠前；
3. 仍相同则按地区名排序。NPC 数量不参与默认排序（它衡量的是该地区现成的劳动力，和建厂收益不是一回事），但可以单独点「NPC」列查看。

**自定义排序**：点「排序」后面的标签换一列（综合 / 物产 / 污染 / NPC），再点一次同一标签切换升降序；选择记在本地，下次打开面板还是这一列。默认方向：综合、物产、NPC 从高到低，污染度从低到高（污染越低越好）。资源产区与工业区最高只有 5 级，单独排序区分度太低，所以不提供手动排序，需要时看「综合」。

「物产」排序先按**加成总和**从高到低；总和相同的地区再按**主物产**（加成最高的那一项，并列取先出现的）聚拢，同主产物的连成一片，不会出现同是「谷物 30%」却被别的 30% 产物隔开、也不会出现 30% 的谷物排到 5% 的铁后面的情况。子标签栏固定在上方，只有列表滚动，列表再长也能随时切子面板。

**跳转**：每行右侧箭头直接打开游戏自己的 `/region/{region_id}`（自动补语言前缀，SPA 内切换，失败才整页跳），落地后不会替你点任何按钮。

**请求规模**：一轮约「国家数 + 1」次请求（目前 53 个国家），3 并发、每次间隔 60ms；打开「工业」时自动抓一轮，之后点「刷新地区」才会再抓。地区清单走 `regionFeed` 的共享缓存（5 分钟），「商品」的领土检查、市场页的地区快捷跳转用的是同一份，同一个国家 5 分钟内只请求一次；没有凭据时只提示、不发请求，凭据到位后自动补一轮。

**已知限制**：地区数据来自游戏接口，抓取那一刻的等级与污染，随时会因为别人建厂 / 战争而变；污染度按百分数直接扣减到综合分上，只是排序参考，不等于游戏内实际产量公式。

## 工商 · 税费

「税费」是「工商」页下的第二个子面板：想知道在哪个国家开厂、摆摊、雇人更划算之前，先把各国的税负和最低工资摆在一起看。它和「工业」共用同一套子标签与排序交互（点一次换列、再点一次切换升降序，选择记在本地）。

**数据**：`/countries/summary` 里每个国家的 `laws`：

- `laws.vat` → 增值税（百分数，13 表示 13%）；
- `laws.import_taxes` → 进口税；
- `laws.minimum_wage` → 最低工资（当地法币）；
- `laws.work_tax` → 工资税（百分数）。

summary 没带这些字段（或只带了一部分）时，才会补一次 `GET /countries`，把缺的几项合并进来——这份结果和「商品 · 销售」的税率共用同一个缓存，不会重复请求；已经拿到的字段不会被覆盖。

**行内排版**：第一行是三种税（增值税 / 进口税 / 工资税），第二行是税前最低工资（含折金）与它对应的最低工资税金，两行固定分组，窄面板里也不会把两者拆开。最低工资标成「税前」，是因为游戏里的最低工资是招聘岗位的 gross 工资（雇主按这个数付钱），员工到手还要扣掉工资税。

**折金**：税前最低工资与最低工资税金都按「卖法币换黄金」的最优价折算（吃别人的买单，与「商品 · 销售」同口径，不是买币价）。标题行末尾会标出该国法币代码，方便和「汇率」页对照。某国货币在当前市场没有买单时，两列都留空（不按 0 算），按税前最低工资 / 最低工资税金排序时这类行永远排在最后。

- 税前最低工资折金 = 税前最低工资 × 汇率；
- 最低工资税金 = 工资税 ÷ 100 × 税前最低工资 × 汇率。

**默认排序（「综合」）**：先比增值税 + 进口税，从低到高；总和相同的国家里，最低工资税金（折金）更低（也就是雇一个人被抽走更少）的排前面；仍然相同再比进口税，最后按国名。这串同值规则方向固定，点成倒序也不会反过来。

**自定义排序**：标签顺序与行内一致——综合 / 增值税 / 进口税 / 工资税 / 税前最低工资 / 最低工资税金。增值税、进口税、工资税按比例，税前最低工资与最低工资税金按折金；点一次换列、再点一次切换升降序，缺汇率的行无论升序降序都排最后。绿色高亮（第一名）只在默认「综合」从低到高时标出。排序标签不带悬浮说明，规则以本节为准。

**固定头部**：搜索框、排序标签、状态栏与「刷新数据」固定在面板顶部，只有下面的国家列表滚动，列表再长也能随时改排序或搜索。

**搜索**：顶部输入框按中文国名、英文国名（不分大小写）与法币代码筛选，三者任一命中即显示，清空恢复全部。输入时按键会被拦在插件内部，不会冒泡成游戏的快捷键，写着写着页面跳走的情况不会发生。

**国籍与位置高亮**：读到账号后，「玩家国籍国」与「当前所在国」在列表里就地高亮——蓝 = 玩家国籍、橙 = 当前位置，行名右侧带标签；两国是同一个国家时合成一个标签「玩家国籍 · 当前位置」，不说两遍。这里**不置顶**：「汇率」置顶是因为全球换汇绕不开本国与本币，而这页是拿全球数据横向对比、按列排序选产业地点，多插两行会打乱排序观察；高亮同样能一眼找到自己，还不影响「第一行就是最优」的读法。数据来自 `playerFeed`（`POST /account/getuser`，2 分钟缓存，与「汇率」的置顶、「商品」的本国判断共用同一次请求），只取国籍 id 与所在国 id，只存内存、不展示原值、不落盘、不打日志。

**流亡政府**：领土检查复用 `regionFeed`（`GET /country/regions?country_id=…`，按国家缓存 5 分钟，与「工业」「商品」的领土检查共用同一份）。已失去全部领土的国家从主列表剔除，单独放到最底部的「流亡政府 · 已失去全部领土」一栏；栏内仍按同一套规则排序，但不参与「最优」高亮。

**请求规模**：打开「税费」先确认汇率（命中 `fxFeed` 的 10 分钟缓存就直接用，否则拉一轮全球挂单，与「汇率」页共用），再查领土（命中 `regionFeed` 的 5 分钟缓存就直接用，否则每个国家一次请求，与「工业」共用）。两段串行执行，避免同时把两条并发流水线都打开；点「刷新数据」会强制重查领土。没有凭据时只提示、不发请求，凭据到位后自动补一轮。

## 如何新增一个功能

每个功能就是一个带 `id / title / mount` 的对象，注册后会自动出现在标签栏里，首次点开时才执行 `mount`（懒加载）：

```js
window.EclesiarHelper.features.register({
  id: 'market-calc',
  title: '行情计算',
  order: 20,                       // 越小越靠前，默认 100
  mount(pane, ctx) {
    pane.innerHTML = '<p class="eh-note">在这里渲染你的界面</p>';

    // 订阅 SPA 路由变化
    const off = ctx.route.onChange((path) => {
      ctx.log('路由变化：', path);
    });

    // 定时器、监听器等清理逻辑交给框架回收
    ctx.onDestroy(off);
  }
});
```

`ctx`（功能上下文）提供：

| 字段 | 说明 |
| --- | --- |
| `ctx.id` / `ctx.version` | 当前功能 id、插件版本 |
| `ctx.shadow` | ShadowRoot，需要挂载自定义样式时可用 |
| `ctx.ui` | `open() / close() / toggle() / isOpen() / resetBall() / resetPanel()` |
| `ctx.ui.reposition()` | 功能内容高度变化后调用，重新测量并保持顶部位置 |
| `ctx.storage` | 按功能自动加前缀的 `get / set / remove`，互不串键 |
| `ctx.route` | `current`（当前路径）与 `onChange(fn)`，返回取消订阅函数 |
| `ctx.onDestroy(fn)` | 注册清理回调，`destroy()` 或卸载时执行 |
| `ctx.log(...)` | 带功能前缀的调试日志 |

面板内可复用的样式类（均在 Shadow DOM 内）：

`eh-section`、`eh-h3`、`eh-kv`、`eh-note`、`eh-callout`、`eh-row`、`eh-btn`、`eh-btn--ghost`、`eh-links`、`eh-mono`、`eh-empty`。

控制台也可直接调用：

```js
EclesiarHelper.ui.toggle();
EclesiarHelper.ui.open();
EclesiarHelper.features.list();
EclesiarHelper.route.current;
EclesiarHelper.destroy();
```

## 设计说明

- **为什么用 Shadow DOM**：游戏是 Vite 打包的 React 单页应用，全局 CSS 变量、`button` 重置、字体规则都很常见。Shadow DOM 能彻底隔离两边样式，插件 UI 不受游戏改版影响；样式表优先用 `adoptedStyleSheets` 注入，规避站点 CSP 对内联 `<style>` 的限制。若浏览器不支持构造样式表、回退的 `<style>` 又被 CSP 拦截，会检测到并写入一段最小内联样式（CSSOM 不受 `style-src` 限制），保证入口仍可见可点，同时在控制台告警。
- **为什么单文件无构建**：油猴的安装体验就是「一份文本」，引入打包器会让每次改动都要构建、复制，反而增加维护成本。脚本内部已按「外壳 / 悬浮球 / 面板 / 路由 / 功能」分节，便于定位与修改。
- **挂载点**：宿主是 `body` 下 0×0 的 `position: fixed` 容器，不占布局、不挡点击（子元素单独开启 `pointer-events`）。
- **尺寸与位置**：悬浮球位置按视口比例保存，缩放后按比例还原；面板未固定时跟随悬浮球，固定后保留绝对位置。窗口缩放、`ResizeObserver`、`visibilitychange` 三路都会触发重新约束——后台标签页里浏览器可能暂停 `resize` 事件与渲染回调，回到前台会立即校正。
- **只读、按需、不轮询**：只有「汇率」「商品」两个标签在你主动打开或点刷新时读取公开挂单接口，且两者共用同一份汇率缓存；插件不写游戏数据、不自动下单。唯一会周期性拉取的是「商品」页的「自动展示商品比价」（默认关闭，玩家主动确认后才生效）：它按 10 分钟缓存过期才刷新、只在前台标签页跑、失败后退避 5 分钟，并随时可以关掉。
- **更新只拉元数据**：版本号单独放在 `eclesiar-helper.meta.js`，油猴的 `@updateURL` 与「设置」页的检查都只请求这个几 KB 的文件；确认有新版本才需要下载脚本本体。
- **不碰账号**：登录 JWT 只在内存中转存，不落盘、不打印、不上报；唯一落盘的是玩家在「设置」页主动生成 / 粘贴的专用 API 密钥，它只用于插件的公开数据查询，同样不打印、不上报。「销售」判断免不免进口税、汇率页置顶本国货币、商品市场上架表单的计价币种，会用 `POST /account/getuser` 读一次当前账号（只认登录凭据，专用密钥会 401，所以不用密钥），但只取国籍 id 与当前所在国家 id 存内存，响应里的其它字段（包括 `bearer`）不读、不显示、不上报。
- **已知边界**：如果游戏日后给 `body` 加 `transform / filter`，`position: fixed` 的参照系会改变，届时需要调整挂载策略；目前游戏未使用这类样式。
